## 驗證結果

- 單元／服務回歸：77/77 組通過（`npm test`）。
- HTTP 回歸：13/13 組通過（`npm run test:http`）。
- 真實瀏覽器回歸：10/10 組通過（`npm run test:e2e`）；新增測試註冊於 `tests/suites.json`。
- 7 頁 × 3 寬度（1440、768、390）× 深淺色，共 42 種頁面版型無整頁橫向溢出。
- 品質校正：1000 段長紀錄、長標題、反覆勾選與取消、全取消、鍵盤操作、空紀錄，未發生頁面錯誤或誤觸 API。
- 兩張 Grafana 報表：64 個查詢成功執行，無 PromQL 錯誤；27 個查詢在檢查當下無樣本，未將空資料誤判為成功率或零延遲。
- 型別、架構、五語系檢查與 Web 正式建置通過。

## 已修正

1. 本機 Diarization 卡片原先直接切換模型，沒有開啟設定／API 測試分頁。現在所有本機卡片均可開啟視窗；由服務管理的設定唯讀，保留測試入口。
2. 環境提供的模型原先能編輯，但重整後會按既有環境優先規則還原。這些卡片改為唯讀；註冊視窗不再允許靜默取代由環境管理的摘要／講者服務。
3. 切換註冊用途時會清除暫存 API key，避免將前一用途的 key 帶入另一用途。
4. 模型視窗增加 Escape 關閉、Tab 焦點範圍與關閉後焦點還原；關閉會取消未完成的 API 測試。
5. 翻譯摘要進行中切回原文，不再以翻譯狀態遮住原文；新增取消翻譯，切換紀錄或離開頁面也會中止請求。
6. 原文摘要前後有空白時，譯文不再因前後端比對文字不同而無法寫回。
7. 品質校正的翻譯階段納入紀錄操作鎖定，並在資料更新函式再檢查，避免已開啟的編輯欄位於校正期間覆寫資料。
8. 品質校正的 Diarization 請求會指定選定模型；HTTP 失敗及空講者結果會報錯並保留原資料。
9. 切換、關閉及重新開啟紀錄時會清除逐字稿搜尋；Escape 可關閉紀錄／下載選單，下載進行中不會被 Escape 提前關閉。
10. 長篇差異表改為 memo，勾選修正項目不會重算整份逐字差異。
11. 帳號篩選選中的部門即使因刪除帳號而暫無資料，仍保留選單值，避免畫面顯示 All 卻實際套用其他條件。
12. 紀錄操作選單的裝飾圖示不再混入無障礙名稱。

## 測試邊界

瀏覽器操作以正式 Web bundle 和隔離帳號／API 執行，會注入失敗、延遲、取消及晚回應，不寫入現有使用者的紀錄。Grafana 對現行報表做唯讀查詢檢查。未對每一個外部模型供應商重新執行實際 ASR／翻譯／講者推論；上游品質與即時可用性不由這份 UI 回歸結果保證。
