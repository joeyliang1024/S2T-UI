# 2026-10-26 驗證結果

500 人連續 600 秒、**每人每 3 秒一條 ASR→翻譯鏈**的容量與錄音完整性通過。但**每 2 秒的極限模式未通過**，瀏覽器翻譯 P90 為 **3.023 秒**，仍未達低於 3 秒的延遲目標，不能稱為全面驗收通過。

## 實際結果

| 條件 | 每 3 秒／次 | 每 2 秒／次極限 |
|---|---:|---:|
| 不同 NT 使用者 | 500 | 500 |
| 音訊生產時間 | 600.000 秒 | 600.874 秒 |
| 已送出／目標字幕鏈 | 100,000／100,000 | 149,376／150,000 |
| 排程丟棄 | 0 | 27,126 |
| HTTP 錯誤、重試 | 0、0 | 0、0 |
| 最終失敗使用者 | 0 | 0 |
| 錄音完成／SHA-256 回讀／清理 | 500／500／500 | 500／500／500 |
| 容量判定 | 通過 | 未通過 |

每輪錄音皆為 9.6 GB，使用者與 frame 有獨立標記。每 3 秒測試的 ASR、翻譯各有 100,000 次 HTTP 200；實際瀏覽器探針 250 則字幕與翻譯皆完成、無瀏覽器或 HTTP 錯誤。探針 ASR P90 為 1.727 秒、翻譯 P90 為 3.023 秒；這些是原始樣本百分位數，沒有四捨五入成「達標」。


## 修正與效能

- 登入介面只使用 NT 與密碼，移除重複 Account 顯示，保留舊資料內部相容；分享設定明確儲存，修正表單與對齊。
- 錄音採不可變分塊、短 SQL 提交、帶租約的完成流程及原子參照／刪除保護。慢物件儲存不再長時間占用資料庫交易；OPFS 與跨分頁 outbox 有有限等待、晚到寫入隔離與確認後清理。
- 小於等於 256 KiB、已知長度且不需正規化的 ASR 音訊直接使用記憶體；大型、串流與正規化維持有界暫存檔。HTTP 提前有限容量控制，健康檢查使用獨立連線池。
- ASR／翻譯使用有界 aiohttp session，禁止 Cookie 轉送、重新導向與自動 POST 重播；摘要串流維持原流程。Linux loopback 客戶端 CPU 平均由 2.292 秒降為 0.250 秒，約降低 89%；這不是整體吞吐提升的百分比。套件原本已在鎖檔內，版本未變。
- 減少冪等 SQL 往返，增加過期索引；清理採單一 worker 擁有的短交易與分批 DELETE，保留活動租約及 SKIP LOCKED。Redis 連線取得有界且可並行，術語檔同時讀取合併。
- Nginx upstream keepalive、動態 DNS、檔案描述元與記憶體預算修正，保留 URI 與串流；實際容器連線重用及上游 IP 更換測試通過。
- 每 Pod 一個受監督程序彙整監控指標，每 15 秒原子發布快照；API 不執行大量序列化，快照超過 45 秒回 503。共用工作佇列在 Pod 內取最新 worker 值、跨 Pod 取最大值，避免舊最大值殘留或重複加總。

成熟做法依據：[aiohttp session／連線池](https://docs.aiohttp.org/en/stable/client_reference.html)、[PostgreSQL 分批 DELETE](https://www.postgresql.org/docs/current/sql-delete.html)、[Nginx keepalive](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive)。

## 功能、安全與計時

- 後端完整回歸 **84 通過、1 跳過**，含真實隔離 PostgreSQL、跨 Pod CAS／冪等／刪除競態、取消、逾時、模型傳輸與監控程序恢復。
- 前端型別、架構、**54／54 單元測試腳本**與正式建置通過；Playwright 本機瀏覽器 fallback 已提供。
- 部署後完整 Web 流程、真實 Chrome 收音及歷史保存、FFmpeg、Silero、聲紋、雙 Pod JWT／錄音接續／登出撤銷、Grafana／PromQL 與瀏覽器 count／sum 精確比對通過。
- npm（含開發相依）及 Python 鎖檔 71 套件、本機安裝 78 套件、完整音訊容器 65 套件，重新稽核皆為 **0 已知漏洞**。最終映像套件版本與稽核輸入一致；不含作業系統套件，也不代表未知或未來漏洞不存在。
- ASR／翻譯總耗時從 middleware 接到請求起算，包含 HTTP 排隊、認證、限流、上傳及模型往返。模型欄位不是純推論；前端剩餘時間包含代理、瀏覽器及傳輸，不是純網路。Grafana 百分位數是直方圖估計，不能當作原始精確百分位數。
- 清理後 Prometheus 與主機時間差約 **0.308 秒**。指標另有最多約 15 秒再加抓取間隔的更新延遲，與時鐘偏差不同。

## 瀏覽器儲存與清理

OPFS 約每 2 秒提交；網路上傳獨立以最多 1 MiB、15–30 秒期限分批，停止時送出尾段，僅在持久化確認後推進與清理。實際 Chrome 阻塞上傳 600 秒後，58,754,560 bytes、307 次提交完整恢復，沒有暫停收音壓力事件。另以 96 kHz、30 倍即時速度產生 600 秒音訊，115,200,000 bytes 回讀一致；寫入卡住、配額與關閉失敗另有注入測試。

負載中遠端積壓最高 34 秒（每 3 秒測試）／42 秒（每 2 秒測試），不代表本機寫入被暫停。這些本機測試不是 500 個真實瀏覽器同時執行。

已依 UUID、NT、部門逐一核對並刪除 **505 個合成測試身份**，保留其他 2 個身份。測試 Pod／ConfigMap／Secret 與私有 JWT 檔已移除，刪除後測試 JWT 回傳 401。未清除使用者瀏覽器網站資料。服務維持啟動：[Web](http://127.0.0.1:5173/)、[Grafana](http://127.0.0.1:3000/)。

## 環境與適用範圍

專用 Colima VM 為 10 CPU、10 GiB RAM、96 GiB 資料磁碟；負載產生器、模型 mock、PostgreSQL、MinIO、Redis 與監控共用 VM。前端 1 Pod（r14、512 MiB 上限），後端 2 Pod（r24、各 4 個 Uvicorn worker、3 GiB 上限），清理後均就緒且零重啟。每 worker 主池 16、保護池 16+1、健康池 1：穩態最多 272、滾動至 3 Pod 最多 408 條；測試 PostgreSQL 上限 448 且使用 PVC。

ASR 與翻譯 mock 各固定等待 500 ms。容量負載為 500 個不同 NT 的 **16 kHz、單聲道 16-bit 虛擬 PCM**，不等於 500 個實體瀏覽器、48／96 kHz 全員上傳、真實模型準確率／運算、WAN 或所有背景工作同時滿載。每 3 秒條件對應正常模式連續發話的分段上限；自然停頓可能更頻繁，不能保證所有說話模式都有相同容量。最終組裝／回讀／刪除採 8 人並行收尾，與 600 秒生產時間分開。

容量及完整 Web／雙 Pod／監控的實測基線為 r23；最終部署 r24 僅刪除未使用匯入，Ruff 與 10 項針對性回歸皆通過，登入／ASR／翻譯最終串接回傳 200。套件版本與行為不變。
