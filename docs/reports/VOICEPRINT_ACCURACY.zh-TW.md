# 聲紋比對準確度與 CPU 成本量測報告

> 依據 sherpa-onnx 原始碼（`sherpa-onnx/csrc/`）與本專案現況的對照分析。
> 對應 `docs/research/K8S_SCALE_PLAN.zh-TW.md` 的「聲紋品質」與「音訊前處理」章節。

---

## 一、sherpa-onnx 的做法（我們要對齊的基準）

### Diarization 管線（`offline-speaker-diarization-pyannote-impl.h`）
1. pyannote segmentation，滑動 window 切 chunk，powerset multi-label。
2. `ExcludeOverlap()`：**重疊發言的幀整幀剔除**，不參與 embedding。
3. 每個 `(chunk, speaker)` 各算**一筆** embedding；該 speaker 幀數 `< 10` 跳過；**NaN 丟棄**。
4. 聚類 `fast-clustering.cc`：每列 L2 正規化 → 距離 `1 - cosine` → **complete-linkage** → 用 `num_clusters`（已知人數時優先）或 `threshold`（預設 0.5）切樹。
5. `min_duration_on` 預設 **0.3s**、`min_duration_off` 預設 **0.5s**（過濾與合併）。
6. 可選 `compute_confidence`：每個 embedding 的 **silhouette** → 與 segment 重疊區間平均 → 該段信心值。

### 識別（`speaker-embedding-manager.cc` + 官方 demo）
- 註冊：`Add(name, vector<vector<float>>)` = **多樣本 embedding 相加（等價平均）→ L2 正規化 → 存一筆**。
- 比對：query L2 正規化 → 內積（cosine）→ 取 max → 與 threshold 比較；官方 demo `--threshold` **預設 0.5**。
- **沒有 margin、沒有共識機制**（這兩項是我們自己加的，方向正確但數值需以實測校正）。

## 二、根因診斷

| # | 根因 | 位置 | 影響 |
|---|---|---|---|
| R1 | 把一個 SPEAKER_XX **整場所有 segment 串成一條**只算 1 筆 embedding | `server/sherpa-diarization.cjs:107-129` | 分群錯誤時 = 混合向量 → 全線掉分（拒識）或飄到別人（錯配）；**也是最大 CPU 浪費**（輸入可能幾十分鐘） |
| R2 | 查詢端**沒有** ExcludeOverlap / 短段過濾 / NaN 檢查 / 信心值 | 同上 | 重疊、短促、噪聲段污染 embedding |
| R3 | 註冊僅 **1 筆、3 秒**、品質檢查只有 rms/duration/削波 | `index.cjs:733-744`、`sherpa-diarization.cjs:41-51` | 同人分數變異大；無 VAD 語音比與 SNR 檢查 |
| R4 | 註冊音訊（乾淨麥克風）vs 比對音訊（會議、可能經 dynaudnorm/denoise/遠端混音）**音訊域不一致** | 兩端前處理不同 | 同人分數系統性偏低 |
| R5 | `threshold=0.65`、`margin=0.05` **無資料支撐** | `index.cjs:245-248` | 太高→漏標、太低→錯配 |
| R6 | diarization `threshold:0.5` 固定、`minDurationOn/Off=0.25/0.35` 比預設更短、未開 confidence | `sherpa-diarization.cjs:70-74` | 上游分群更雜、碎段流入比對 |
| R7 | `identityCandidates` 對同 NT 取 **max** | `voiceprint-matching.cjs:2-10` | 註冊筆數越多越易被噪聲樣本拉高 |
| R8 | `resampleMono` 無 low-pass 線性插值 | `sherpa-diarization.cjs:26-35` | 48k→16k alias，輕微傷 embedding |

### CPU / 排程根因
| # | 根因 | 位置 | 影響 |
|---|---|---|---|
| C1 | Silero **逐 32ms 一次 `session.run`、掃全檔、回傳全量 `probabilities`** | `silero-vad.cjs:45-51,69` | 1 小時 = 112,500 次呼叫 + 112,500 物件跨 thread 序列化 |
| C2 | 每次 VAD 都 `readFileSync` + sha256 整個模型檔 | `silero-vad.cjs:36→13-15` | 每 job 重複讀檔雜湊 |
| C3 | 單一 pool：`size=1`、`maxQueue=8`、`timeout=120s` 固定、**無搶佔** | `sherpa-worker-pool.cjs:13,65-79` | 一個巨型 background job 期間，註冊/VAD 只能在佇列插隊但無法中斷進行中 job；長會議可能逾時被砍 |
| C4 | **每個 job 都複製整份 WAV**（structured clone + `Buffer.from` 第二次複製） | `sherpa-worker.cjs:25` | 一場會議 N+2 次全檔複製 |
| C5 | VAD、比對、embedding 分散成多個 job | 各自 `pool.execute` | 每步都要重新排隊、重新序列化音訊 |
| C6 | 聲紋標註在 `/api/diarizations` **同步**執行 | `index.cjs:877-881` | 佔住 worker，拖慢 diarization 回應 |

## 三、目標

1. **準確度**：錯配率（把 A 標成 B）大幅下降；寧可拒識維持 `SPEAKER_XX`，絕不錯配。
2. **CPU 時間**：標註流程總耗時 `≤ 音檔時長 × 0.2`（可配置預算）；註冊與 VAD 的互動延遲不被長任務拖垮。
3. **可量測**：所有參數（門檻、margin、塊數、預算）依實測分佈決定，不猜。

## 四、量測方法

### 4.1 評測工具與指標

本報告的數字全部由下列指令重現：

| 指令 | 用途 |
| --- | --- |
| `npm run voiceprint:eval` | 同人／異人分數分佈、EER、指定門檻下的正確／錯配／拒識率（`scripts/evaluation/eval-voiceprint.cjs`） |
| `npm run voiceprint:eval:timeline -- --tsv <標註時間軸.tsv> --audio <來源.wav>` | 有 ground truth 句級時間軸的聲紋評測（`eval-voiceprint-timeline.cjs`） |
| `npm run diarization:eval:timeline` | 整段 diarization 的句級正確率／DER；同一次執行比較主執行緒直呼叫與 worker pool 兩條路徑 |
| `npm run diarization:eval:corpus` | 多檔 × 多門檻批量評測與匯總 |
| `npm run diarization:rttm:tsv` | RTTM → 句級 TSV |
| `npm run diarization:labels:smoke -- --verbose` | 生產碼重放：現行／Stage 1／Stage 2 三列逐檔數字，並斷言不得劣於現行 |
| `npm run voiceprint:blocks:smoke`、`silero:vad:smoke`、`diarization:smoke`、`diarization:preview:smoke` | 分塊、VAD 喂法、回應契約回歸 |

指標：

- **聲紋**：錯配率、拒識率、正確率、EER、score 分佈。決策原則：寧可拒識維持 `SPEAKER_XX`，絕不錯配。
- **語者分離**：句級正確率（每個評分單位以最優映射對真值評分）、DER（miss/confusion）、預測語者數、過切／合併檔數。
- **標籤穩定度**（即時預覽）：**句翻轉**（同一句在相鄰兩個可觀察 tick 拿到不同標籤，分母 104 個比較機會）、**語者跳動**（每位真值語者每 tick 的多數標籤改變，分母 122）、**每語者標籤／distinct**（`SPEAKER_01 → 03 → 05` 一類的膨脹）、**標籤純度**（同一穩定標籤的句子時長中屬於其最多數真值語者的比例）。句級正確率作為對照組：所有策略在同一視窗內都是一對一，重新命名不改變分割品質——穩定度數字講的是標籤穩定，不是辨識準確度。

### 4.2 Ground truth 資料

- **TTS 對照組（先驗證工具本身）**：純語音素材，same 0.839／diff 0.145，門檻 0.65 下正確率 100%。
- **對唱素材（領域外壓力測試）**：`music/梁山伯與茱麗葉_句級Speaker時間軸.tsv`（句級 start/end/speaker，曹格、卓文萱，含和聲標記）＋對唱 MP3（16 kHz mono WAV，238.4 s）。註冊前 4 句、其餘 25 句為測試集，和聲句另計；同一句永不會與自己比對。
- **VoxConverse dev（多位真人會議標註）**：[VoxConverse](https://www.robots.ox.ac.uk/~vgg/data/voxconverse/) dev set，216 段錄音（1 ch / 16 kHz / PCM16）＋216 份 RTTM 標註；改用 KAIST 鏡像分段並列下載，最終 1,988,647,478 bytes、**MD5 `2a6e07e7473d9841abb132554a698a36` 與官方一致**（`unzip -t` 通過，放在 `tmp/`，已加入 `.gitignore`）。語者數中位 4、最多 20，216 檔中 194 檔 ≥ 2 位語者。固定取樣 20 檔（`cobal,ikgcq,blwmj,syiwe,uatlu,pgkde,bwzyf,ycxxe,ypwjd,wjhgf,jhdav,cqaec,kbkon,ydlfw,jtagk,qjgpl,eziem,gocbm,xmfzh,wewoz`），共 3385 s、真值語者均值 5.3、評分句 423 句。

  ```bash
  # 216 份 RTTM → 句級 TSV（產出 tmp/voxconverse/tsv/<id>.tsv）
  npm run diarization:rttm:tsv

  # 多檔 × 多門檻批量評測（--thresholds 逗號分隔，可加 --min-duration-on）
  npm run diarization:eval:corpus
  ```

  原始數字留檔：`experiment/evaluation-reports/diarization-voxconverse-thresholds.json`（0.5/0.7/0.8）、`-thresholds-b.json`（0.75/0.85）、`-mindur.json`（0.8＋`MIN_DURATION_ON=1.0`）；每個 JSON 的 `thresholds[]` 陣列即為彙總表的列，`results[]` 為逐檔明細。
- **即時預覽模擬**：11 檔（對唱 238.4 s ＋ 10 個 VoxConverse 檔）、77 個 tick、262 個可評分句子。視窗 45 s／tick 30 s、門檻走自適應 0.7，與現行一致。以 `tmp/preview-cache.cjs` 把每個視窗的 sherpa 原始輸出與「(tick, 標籤)」的一個 per-label 聲紋向量凍結成 JSON，所有策略在同一份快取上比，差異只來自匹配規則；視窗成本與聲紋成本以 `tmp/window-cost-probe.cjs`、`tmp/embedding-cost-probe.cjs` 量測。生產碼重放入口 `npm run diarization:labels:smoke` 已進 `scripts/`，可長期重現；快取在 `.gitignore` 的 `tmp/`，重現需先重建。

### 4.3 影響量測有效性的修正

三處缺陷若不修正，量測結果不可用：

1. **Silero VAD 喂法（576 樣本契約）**：官方 wrapper 餵 **64 樣本 context ＋ 512 樣本窗 = 576 樣本**；本專案只餵 512，不會報錯但 recurrent state 追不到語音，機率全部塌成 ~0.003（官方原話：*probabilities stay near zero*）。後果：UI 勾「使用 Silero VAD」時 `model-adapter.ts` 判定無語音就直接丟棄該段、字幕完全不出；`S2T_VOICEPRINT_VAD=1` 門檻把所有區塊（含正常語音）全部否決 → 100% 匿名；`/api/audio-processing/silero-vad` 永遠回 `speech: []`。修正後實測（回歸測試 `npm run silero:vad:smoke`）：

   | 素材 | 語音比例（修正前） | 語音比例（修正後） |
   | --- | --- | --- |
   | 語音 TTS-A / TTS-B | 0.000 / 0.000 | **0.997 / 0.983** |
   | 音樂前奏 | 0.000 | 0.000 |
   | 唱歌（曹格主歌） | 0.000 | 0.233 |
   | 對唱整首 | 0.000 | 0.024 |

2. **環境變數解析**：`Number(process.env.X || '')` 在變數未設定時得 `Number('') = 0`，通過 `[0,1]` 範圍檢查 → 聚類門檻新預設 0.8 實際傳入 0、原生層退回落後到 0.5（實測仍是 8 位語者）；`envNumber()` 同類缺陷讓任一 `S2T_VOICEPRINT_*` 空值靜默變 0。修正：未設定／空／空白字串一律回傳預設值。要求 `> 0` 的 `positiveNumber`／`positiveInteger`（`sherpa-worker-pool.cjs`）天然不受影響。
3. **句級評分反向映射**：評分曾拿 `truth→prediction` 的 map 去查 prediction，句級正確率全為 0%（假陰性），會誤導門檻選擇；建立 `prediction→truth` 查表後重測。

## 五、量測結果

### 5.1 聲紋比對準確度

**對唱素材（唱歌＋配樂）**：

```
same-singer    n=144  min 0.017  median 0.480  max 0.876
diff-singer    n=156  min 0.010  median 0.476  max 0.942
EER = 0.48（等同隨機猜測）
門檻 0.65 / margin 0.05：正確 2/25 (8%)、錯配 1/25 (4%)、拒識 22/25 (88%)
```

任何門檻都救不了（0.65 時 pair-FAR 0.135、pair-FRR 0.896）→ **唱歌＋配樂對語音型 speaker embedding 是無訊號領域**，不是門檻問題。另外量到誤標機制：**純樂器間奏對註冊向量拿到 0.702 分**（> 0.65、領先 0.144），依規則會被標成身分，完全是配樂造成。

這是領域外的壓力測試：不能用它宣稱會議／口說場景的錯配率；但它證明了「沒有標註就不能調門檻」以及「音樂素材需要前置否決」。

端到端抽查（19.27 s、兩講者、已註冊 1 人）：`SPEAKER_00` → accept path=fast score 0.995 標為已註冊身分、`SPEAKER_01` → reject reason=below-threshold top1 0.166 維持匿名；extractionMs 435、totalMs 437。embedding 成本見 5.4。

### 5.2 語者分離準確度與聚類門檻

#### 與 sherpa 原生的一致性

`npm run diarization:eval:timeline` 在同一次執行中以完全相同的音訊位元組跑兩條路徑：`diarizeWav(audio)` 主執行緒直呼叫原生 sherpa，與 `sherpaWorkerPool.execute('diarizeWav', …)`（gateway／durable job 實際走的 worker pool 路徑）。以 `start|end|speaker` 序列化後逐段比對：

| 音檔 | 段數（pool） | 段數（直呼叫） | 結果 | 直呼叫 / pool 耗時 |
| --- | --- | --- | --- | --- |
| `duet.wav`（238.4 s 對唱，threshold 0.8） | 26 | 26 | **逐段完全相同** | 41.8 s / 43.0 s（RTF ≈0.175） |

pool 包裝層（佇列、timeout、分池、隔離、`awaitIdle`）**沒有改變 sherpa 的輸出**；差異只可能來自 `labelDiarizationTurns` 的語者再命名，而沒有註冊聲紋時那一步原樣返回。

#### 端到端（真實 HTTP 路由＋renderer 指派）

以 `duet.wav` 呼叫 `POST /api/diarizations`，回傳的 turn 交給 renderer 的 `parseSpeakerTurns` → `stabilizeSpeakerTurns` → `assignSpeakersByOverlap`（0.35 覆蓋率門檻），再以句級 TSV 對答案：

| 指標 | 數值 |
| --- | --- |
| `POST /api/diarizations` | **200**，40 959 ms（238.4 s 音檔 → RTF 0.172）、26 段（24.3 s–215.6 s） |
| 字幕已標語者 | 31 / 40 句 |
| 句級正確率 | **22 / 27 = 81.5%** |
| 時間加權正確率 | 67.6% |
| 標籤對應 | `曹格 → SPEAKER_01`、`卓文萱 → SPEAKER_02` |
| 錯配 | 5 句，全部是 `曹格` 被指到 `SPEAKER_02` |

與 library 級的 82.1% 一致（差異來自 renderer 要求每句覆蓋率 ≥0.35 才標註，未達標的句子計入 `unlabelled` 而非錯配）。「與 sherpa 一致」與「端到端效果」兩層都驗證通過。

#### 即時預覽（45 s 滑動視窗）

即時語者辨識走另一條路：renderer 只保留最近 45 s（`maximumPreviewSamples = sampleRate * 45`），每 30 s 把整個視窗重貼一次 `POST /api/diarizations`，再用 `assignSpeakersByOverlap`（覆蓋率 ≥0.35）指派到字幕；視窗起點隨 chunks 裁剪累加，實際視窗即 `[t-45, t]`、`t = 30, 60, …`。每個 tick 獨立跑真的 `diarizeWav`，再以該視窗內的混淆矩陣做最佳標籤對應：

| 素材 | 門檻 | 每視窗語者數 min/中位/max | 句級正確率 |
| --- | --- | --- | --- |
| 對唱（真值 2 位） | 0.5 | 2 / 3 / 4 | 56.1%（23/41） |
| 對唱 | **0.7** | 1 / 2 / 3 | **65.9%（27/41）** |
| 對唱 | 0.8 | 1 / **1** / 2 | 56.1%（23/41） |
| 旁白（標 1 位） | 0.5 | 1 / 4 / 8 | 65.4%（51/78） |
| 旁白 | 0.7 | 1 / 3 / 8 | 69.6%（55/79） |
| 旁白 | **0.8** | 1 / 3 / 8 | **72.2%（57/79）** |

（視窗週期 30 s 短於視窗長度 45 s，邊界句子會被相鄰兩個 tick 各計入一次，句數因此多於 TSV 行數；這也對應實際體驗——同一句字幕在滑動視窗中會被重新標註多次。）

三個發現：

1. **整段的最優門檻（0.8）不是視窗的最優門檻。** 對唱視窗在 0.8 下 6 個 tick 有 **4 個塌縮成 1 個語者**，兩位歌手被黏成同一人；0.7 恢復到中位 2 個。
2. **原因是證據不足。** 45 s 視窗只有 4~13 段，激進合併會把不同人黏在一起；整段有 26~186 段，證據充足。
3. 旁白視窗在 0.7 與 0.8 的差距只有 79 句中的 2 句（69.6% vs 72.2%），屬噪音；對唱的差距（56.1% vs 65.9%、中位 1 vs 2 群）是結構性的。

#### 聚類門檻掃描與自適應規則

原本 `clustering: { numClusters: 0, threshold: 0.5 }` 是寫死的。以兩份有標註的時間軸掃描（`S2T_SHERPA_CLUSTERING_THRESHOLD`）：

**對唱 `梁山伯與茱麗葉`（真值 2 位歌手，238.4 s / 33 句主唱）**

| threshold | 預測語者數 | DER | miss | confusion | 句級正確率 |
| --- | --- | --- | --- | --- | --- |
| 0.4 | 14 | 80.8% | 24.6% | 56.2% | — |
| **0.5（原預設）** | **8** | **68.0%** | 24.6% | 43.4% | **50.0%**（14/28） |
| 0.7 | 4 | 53.7% | 24.6% | 29.0% | 71.4%（20/28） |
| **0.8** | **3** | **42.4%** | 24.5% | 17.9% | **82.1%**（23/28） |
| 0.9 | 3 | 42.4% | 24.5% | 17.9% | — |

**口說 `what'sub` 影片（60 句全標 `reference`，827 s）** — 檢驗「不能切太碎」這一端：

| threshold | 段數 | 預測語者數 | DER | miss | confusion | 句級正確率 |
| --- | --- | --- | --- | --- | --- | --- |
| **0.5（原預設）** | 194 | **71** | 67.5% | 5.2% | 62.3% | 32.7%（18/55） |
| 0.7 | 186 | 49 | 66.1% | 5.0% | 61.1% | 35.2%（19/54） |
| **0.8** | 185 | 41 | 65.7% | 5.0% | 60.7% | **36.4%**（20/55） |
| 0.9 | 180 | 29 | 63.0% | 4.9% | 58.1% | 33.3%（19/57） |

**決策：改為依輸入長度自適應，而非單一預設值。**

整段（final pass）這端：對唱 DER 68.0%→42.4%、句級正確率 50.0%→82.1%、語者數 8→3；口說端句級正確率 32.7%→36.4%（無回歸）、語者數 71→41。0.8 是**整段**的拐點：0.9 在對唱端不再改善（維持 3 群），口說端句級正確率反而下降。但即時預覽視窗的最優值是 0.7——兩條路徑的最優值不同，最終採用依輸入長度切換：

| 規則 | 套用值 |
| --- | --- |
| 輸入 ≤ `S2T_SHERPA_SHORT_AUDIO_SEC`（預設 60 s） | **0.7** |
| 輸入 > 60 s | **0.8** |
| 設定 `S2T_SHERPA_CLUSTERING_THRESHOLD` | 強制單一值（僅供 A/B 對照） |

理由：**證據越少，越不該激進合併**。60 s 是乾淨的分界——即時預覽視窗上限 45 s，一定落在短側；最終 pass 送的是整段錄音；錄音本身短於 60 s 用較保守的 0.7 也符合同一邏輯。實作：sherpa-onnx 的 `setConfig({ clustering })` 支援逐次設定，在 `diarizeWav` 每次呼叫前依音訊長度套用；worker pool 快取的同一實例以 `typeof instance.setConfig === 'function'` 保護。

自適應開啟後的實測（8 項 smoke ＋ `tsc --noEmit` 全 PASS）：

| 路徑 | 素材 | 套用門檻 | 結果 | 對照（固定 0.8） |
| --- | --- | --- | --- | --- |
| 即時預覽視窗 | 對唱 | 0.7 | **65.9%**（27/41）、中位 2 語者 | 56.1%、中位 **1** 語者 |
| 即時預覽視窗 | 旁白 | 0.7 | 69.6%（55/79） | 72.2%（−2.6 pp＝79 句中的 2 句） |
| 整段 final pass | 對唱 | 0.8 | **82.1%**（23/28）、3 語者、**與 sherpa 逐段相同** | 82.1% |
| 整段 final pass | 旁白 | 0.8 | 36.4%（20/55）、41 語者 | 36.4% |

**取捨**：即時預覽的對唱 +9.8 pp、旁白 −2.6 pp，整段兩端皆不變。取 0.7 是因為 0.8 造成的「兩位歌手被黏成同一人」是結構性錯誤（使用者會直接看到），而旁白那 2 句屬噪音。**注意**：兩份資料都還不是多位真人對話的標註，這個值校正的是「不要過度切碎」，「不會把不同人合併」仍需多人會議標註驗證。原始的 0.5 會把 13 分鐘旁白切成 71 個語者（即時預覽顯示 `SPEAKER_00…SPEAKER_70`），是使用者可見的缺陷，也是改預設值的主要理由。

### 5.3 即時預覽的標籤穩定度

#### 根因分類（現行實作，55 個語者級跳動事件）

| 原因 | 事件 | 佔比 |
| --- | --- | --- |
| greedy 取「時間重疊最大者」，視窗一滑就錨到別人的標籤 | **28** | 51% |
| 15 s 重疊區內完全沒有任何錨點 | **21** | 38% |
| 最佳錨點已被同 tick 的另一個標籤占用 | 6 | 11% |
| 「改用次佳錨點就不會翻轉」 | **1** | 2% |

**主因不是「找不到錨點」，而是「取最大重疊」這個選擇本身不穩定。** 也因此「改用次佳錨點」這類補丁幾乎無效（1/55）。基線為現行生產碼本身：實驗實作與 `npm run diarization:labels:smoke` 在同一份快取上逐檔吻合（14/104、55/122、distinct 128、純度 90.9%），兩個獨立實作互為驗證。

| Op | CPU 時間 | RTF | 說明 |
| --- | --- | --- | --- |
| `sileroVad` | 0.83 s | 0.003 | 首個語音 00:24.9、5 區間／5.8 s voiced |
| `diarizeWav` | 38.0 s | 0.159 | 39 段、**8 個說話者（真值 2）** |
| `extractSpeakerBlocks` | 3.4 s | 0.022 | 156 s 輸入、`transferredBytes = 0` |

- **diarization 佔整條流程約 90% CPU**，是優化主戰場；唱歌是 pyannote 的已知弱項（2 位歌手被分成 8 群），分離度（標籤取自 diarization 分群、非 ground truth）同群 median 0.706、異群 0.547，仍有重疊。
- **聲紋 embedding**：15 秒輸入 ≈ 0.5 s、9 秒 ≈ 0.2 s。逐標籤聲紋 **RTF 0.022**，45 s 視窗約 **0.9 s/tick**，對照 diarization 本身的 5.6 s/tick 是 **+16%**；標籤總覆蓋音訊越多越貴，上限即視窗長度。
- **即時預覽**每 tick diarization 5.6 s（RTF 0.123–0.127）。45 s 視窗／30 s 週期的冗餘為 1.5x（≈16 s CPU/分），是接受的取捨——再降到 1x 需把週期拉到 45 s，會讓即時預覽的語者標籤延遲變差，與「即時字幕優先」相衝突；`stabilizeSpeakerTurns` 依賴時序重疊才能延續標籤，縮短重疊區會直接損害標籤穩定度。早期的 3x 冗餘已由週期 15 s→30 s 減半。
- **錄音層否決**的一次全檔 Silero 掃描 RTF ≈ 0.003，成本可忽略。

## 六、結論與決策

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 聚類門檻 | **自適應：≤60 s → 0.7，>60 s → 0.8**（可用 `S2T_SHERPA_CLUSTERING_THRESHOLD` 強制單值） | 整段與視窗的最優門檻不同；證據越少越不該激進合併 |
| `minDurationOn` | **維持 0.25** | DER 退、合併 +1、覆蓋 −5% |
| 45 s 視窗週期冗餘 | **接受 1.5x，不做增量視窗** | 冗餘已 3x→1.5x；再降需犧牲標籤延遲與穩定度 |
| 評測工具 | `npm run diarization:eval:timeline`（整段）＋ 預覽視窗模擬，與 `voiceprint:eval:timeline` 同構 | 可重現本報告所有數字 |
| 穩定化訊號 | 由「取時間重疊最大的先前標籤」改為**字幕連續性 ＋ √時間重疊 ＋（可選）聲紋相似度**的全域一對一匹配 | 根因是「取最大重疊」不穩定（51%）與無錨點（38%）；字幕連續性直接使用「上一 tick 這行是誰」 |
| 編號策略 | **維持鑄新號（max+1），不回收** | 回收讓句翻轉 14→68、純度 90.9→80.8%；回收能壓低 distinct，但會把同一號碼指派給不同的人 |
| 聲紋門檻 | **0.7** | 拐點：生產實測跳動 55→41（−25%）、純度只 −2.5 pp；0.6 純度掉 6.4 pp，0.8 只剩 −9% 跳動 |
| 預覽視窗長度 | **維持 45 s** | +57% CPU 換來更差的翻轉率與正確率 |
| 聲紋標註排程 | 標註改 background 回填、per-speaker 小 job ＋ hash 快取（對應 K8S_SCALE_PLAN「即時字幕優先於聲紋」） | 見 P4 |

**已上線的穩定化（數字為生產碼實測）**：

1. **Stage 1 — 零成本版（只改 renderer）**：`stabilizeSpeakerTurns(previous, incoming, { captions })`，權重 = 字幕連續時長 ＋ √重疊秒數，匈牙利求一對一。矩陣 ≤ 10×20，CPU 可忽略。實測句翻轉 14→11、distinct 128→122、語者跳動持平（55→55）。
2. **Stage 2 — ＋聲紋版（server 配合）**：preview 的 diarization 回應在請求帶 `x-s2t-speaker-embeddings: 1` 時多回傳 `speaker_embeddings`（每個標籤一個 512 維向量，~6 標籤 ≈ 12 KB）；renderer 以 `parseSpeakerEmbeddings` 取用、把向量落在「穩定標籤」上，權重加 5×cosine（≥ 0.7 才計入）。實測語者跳動 55→**41**、distinct 128→**99**、句翻轉 14→12。
3. **錄音層否決（預設開）**：一次 Silero 掃描整份錄音（RTF ≈ 0.003），若「語音總時長 < 10 s」且「語音比例 < 5 %」同時成立就跳過整輪聲紋標註，回 `vetoed: true`、log `recording-no-speech`。音樂素材的聲紋分數不可信，而真實對話的語音比例是數十百分比，兩條件並用可避免誤傷安靜但真實的錄音。開關：`S2T_VOICEPRINT_AUDIO_VAD`（預設 1）、`_MIN_SEC`（10）、`_MIN_RATIO`（0.05）；逐塊比例門檻 `S2T_VOICEPRINT_VAD` 仍為選配，兩者並存。否決判定放在 `extractDiarizedSpeakerBlocks`（heavy worker 內、免額外複製音訊）；`shouldVetoRecording` 為純函式，整合行為由 `voiceprint-blocks-smoke-test.cjs` 以「大聲但無語音」與真實語音素材雙向驗證。

**成本與上線條件**：聲紋是**選擇性開關**——只有 preview 請求帶 flag，整段後製不帶，避免對整首錄音付出同樣的 RTF 卻沒有任何人讀它；桌面版經 `preload → model:diarize` 轉傳同一個 header。聲紋取不到時（短於 1 s 的標籤、該視窗無乾淨人聲、舊版 server）回應就是沒有該欄位，穩定化退回字幕＋時間重疊，也就是 Stage 1 的行為。

**驗證**：`npm run diarization:labels:smoke -- --verbose`（11 檔快取重放，斷言「語者跳動／句翻轉不得劣於現行」且「＋voice 必須贏過只有字幕」）＋ `npm run diarization:smoke`（含 `extractSpeakerLabelEmbeddings` 的分組、過短與越界略過）＋ `npm run diarization:preview:smoke`（起真實 gateway，驗證有無 `x-s2t-speaker-embeddings` 兩種回應契約）。

**限制**：單一語料（VoxConverse dev）＋ 1 首對唱；104 個句翻轉機會、122 個語者跳動機會，樣本仍小；生產碼量測的字幕**時間範圍**仍以真值句子近似（真實 ASR 字幕的落差以 ±1.0 s 抖動界定）；所有穩定度結論不改變句級正確率與 DER（所有策略下完全不變）。門檻校正與「不會把不同人合併」的驗證仍需要更多位真人對話的標註資料。

## 七、優化計畫摘要（P0–P4）

| 階段 | 內容 | 驗收 |
| --- | --- | --- |
| **P0 量測基線**（決定後續一切數字） | `stats()` 擴充 per-operation 統計（`count / totalMs / totalAudioSec / RTF`）；每次比對記錄 `top1、top2、margin、語音總時長、segment 數、決策結果`；新增可重複的評測腳本（錯配率／拒識率／正確率＋score 分佈） | 跑一次真實會議可取得各 op 的 CPU 秒與 RTF；有一條可重複執行的評測指令 |
| **P1 分層共識**（準確度主戰場，不動資料結構） | 廢除「串接全場」：每 speaker 取最長 3 塊（每塊 10–15 秒、總量 45 秒，有效語音 < 8 秒不比對）；每塊先能量粗篩、必要才呼叫 Silero；Stage-1 只用 block#1 查 top-3 → Stage-2 對 top-3 複驗；決策 `median ≥ threshold` 且命中段數 ≥ 2 且 `top1-top2 ≥ margin` 才標 NT，否則維持 `SPEAKER_XX`；early exit（block#1 ≥ 0.75 且領先 ≥ 0.15） | 評測的錯配率下降；embedding 推論輸入總秒數低於現況；未命中一律維持匿名。風險低：純邏輯替換，不動資料結構、不需重新註冊 |
| **P2 Silero 與 worker 成本** | 模型 sha256 快取；`probabilities` 改 opt-in；VAD 只跑候選塊不掃全檔；ORT `intraOpNumThreads: 1`；推論線程可調；**fast／heavy 分兩個 pool**；timeout 依輸入長度計算取代固定值；**音訊駐留 worker**（`loadAudio` 一次複製 → `audioId` 引用 → `releaseAudio`，全檔複製 N+2 → 1） | Silero CPU 秒大幅下降；註冊／VAD 的互動延遲不被長任務阻塞；單一 job 失敗只影響單一 speaker。P2-1~P2-5 低風險先行，P2-6~P2-8 涉及排隊與生命週期、獨立一輪 |
| **P3 聲紋庫資料模型** | 同身分多次註冊 → `normalize(Σ sample 向量)` 存**單列**（原始 sample 向量存 PostgreSQL，補註冊時重新平均）；`S2T_VOICEPRINT_EMBEDDING_VERSION` bump 觸發重新註冊；註冊品質：最低 ≥10 秒有效人聲、VAD 語音占比與 SNR 檢查、註冊與比對走同一前處理分支（消 R4） | 向量層列數 = 身份數；重新註冊後分數分佈明顯收斂。風險中（需全員重註冊），先確認 P1 的效果再決定是否需要 |
| **P4 排程與門檻校正** | 聲紋標註改 **background**（先回 `SPEAKER_XX`、完成回填）；per-speaker 小 job ＋ `hash(audioKey+speaker+segments)` 快取＋時間預算；依 P0-3 分佈校正 `threshold` 與 `margin`（取代 0.65/0.05）；diarization 參數（`clustering.threshold`、已知人數給 `numClusters`、`minDurationOn/Off`、`compute_confidence`）；若 embedding 是瓶頸則換更快模型（如 CAM++ 192 維，靠 version 機制安全遷移） | `錯誤率/拒識率` 達成目標且可重複；標註總耗時在預算內；互動 op 延遲 P95 不受長任務影響 |

執行順序：

```
P0 量測基線
 ├─→ P1 分層共識（低風險，先拿準確度）
 │     └─→ P3 聲紋庫改造（視 P1 成效決定是否需要）
 └─→ P2-1~P2-5 Silero/線程小改（低風險，與 P1 並行）
       └─→ P2-6~P2-8 分池 + 拆 job + 音訊駐留
             └─→ P4 排程 background + 門檻校正（依 P0/P3 數據）
```
