# 即時字幕與翻譯穩定性修正與 10 分鐘驗證

驗證日期：2026-10-03（Asia/Taipei）。所有驗證使用本機模擬模型，外部模型 API 呼叫數為 0；未使用正式儲存、未部署。

## 修正

- Web gateway 原本每個 IP 每分鐘只允許 30 次翻譯、60 次 ASR；現在已登入請求按帳號與服務分別計算，未登入請求按 IP 計算。仍是每個 gateway 程序的滑動 60 秒窗口，不是跨 Pod 共享額度。
- `S2T_ASR_REQUESTS_PER_MINUTE`、`S2T_TRANSLATION_REQUESTS_PER_MINUTE` 預設各 180；接受正整數，無效值使用預設值。這些是本程式的限制，不會提高模型供應商的配額。
- 本機與上游的 HTTP 429 均保留 `Retry-After` 與 `retryAfterSeconds`。即時 ASR／翻譯停用 SDK 的隱藏重試，由前端統一處理；摘要維持既有重試設定。
- 翻譯先排除正在處理、已完成、同語言及尚未到重試時間的字幕，再取並行名額。自動模式最多 2 筆；節流模式每 900 毫秒最多啟動 1 筆，總並行上限仍為 2；手動模式不自動送出。
- 429 依服務回傳時間等待，缺少資訊時等待 30 秒，不計入一般失敗次數。一般暫時錯誤最多 3 次，兩次重試間隔為 1 秒、2 秒；空白譯文也會重試。400／401／403／404／422 直接顯示失敗，避免無效重試。
- `translationContentRevision` 是可選字幕欄位，舊資料按 0 處理，無須遷移。人工原文／譯文或 ASR 內容變更會失效舊請求；單純講者／時間更新不會。原文修改也會移除已過期的舊譯文。
- 正在翻譯的字幕不合併；合併時保留全部 ASR 文字。取消、設定變更、開始新收音及載入歷史字幕會隔離舊請求。
- 正常停止 ASR 時等待在途請求與排隊段落，滿佇列時先清空佇列再送尾段。HTTP 逾時涵蓋回應本文讀取。ASR 保持單筆串行，佇列上限仍為 4。
- 停止收音後暫停翻譯排程，補翻最多等待 60 秒；超時取消在途翻譯、保留音訊／原文與未完成字幕並顯示提示。未完成字幕可載入即時字幕頁手動補翻。
- 診斷輸出僅含請求耗時、ASR 排隊等待、並行數、429、錯誤、過期結果與未翻譯數；不輸出音訊或逐字稿。翻譯診斷計數從該頁的佇列建立起累計。

## 結束收音後的背景補完與紀錄標籤（追加）

- 停止收音先建立同一筆「執行中」紀錄，立即切到紀錄頁，才等待 recorder／ASR／翻譯／音檔保存；尾段字幕與譯文持續更新該筆紀錄。接續收音仍只有一筆紀錄。
- 卡片與逐字稿視窗顯示「執行中」及階段（尾段字幕、翻譯、保存音檔、最後講者分離）；全部成功顯示「已完成」。錯誤或翻譯逾時顯示「未完成」及原因。舊紀錄缺少新欄位時視為已完成，不需要遷移。
- 有設定講者分離模型時，停止後執行最後一輪完整音檔分離，不受即時預覽開關限制。結果保留譯文、時間戳與人工講者標記，同步更新使用中的音檔版本。
- Web 使用原有 gateway 持久化講者工作；保存工作編號，重新開啟頁面可觀察已提交工作的狀態。工作帶收音代次，過期工作不覆寫新錄音；伺服器在推論前確認對應紀錄與版本已就緒，避免尚未同步時提前推論。
- 遠端版本衝突合併保留同代次已完成的背景結果；僅更新該筆紀錄，保留其他紀錄的本機變更。未修改的即時字幕預览不會在切換紀錄時覆寫最後講者結果。
- 執行中可查看逐字稿；修改、刪除、接續及音檔操作在處理完成後開放，避免與背景寫入競爭。

追加驗證：`npm run caption:background:smoke` 通過。測試直接執行正式停止函式與 gateway 背景工作函式，以可控制的 Promise 模擬 recorder、尾段 ASR、翻譯及音檔保存；使用正式翻譯佇列、講者結果合併與紀錄合併邏輯。驗證立即切頁、尾段即時更新、接續不重複、停止／翻譯／保存失敗標籤、關閉預覽仍送最後講者工作、人工講者與譯文保留、過期代次／工作租約、CAS 衝突及切換紀錄保護。另以實際 React 伺服器渲染驗證三種標籤。

追加 TypeScript、build、字幕虛擬時間回歸、講者分離、i18n 與匯出 smoke 均通過，真實模型與正式儲存呼叫數為 0。以下 10 分鐘瀏覽器報告是原排程修正的實跑結果；本次背景切頁追加修改沒有重新執行 10 分鐘完整產品瀏覽器測試，也未做遠端資料庫整合驗收。

限制：尾段 ASR 與翻譯仍由開啟中的 Web 應用執行，切換應用內頁面可持續；在音檔保存及講者工作交接完成前關閉或重整瀏覽器，不能保證補完。伺服器接手後的講者工作可持續。這次沒有新增可跨瀏覽器關閉的伺服器 ASR／翻譯工作系統。

## 實際 10 分鐘瀏覽器測試

使用 Codex 內建瀏覽器，隔離 localhost 頁面與本機 HTTP 模型；重用正式程式的 EnergyVad、ASR adapter、字幕更新、翻譯佇列、500 筆顯示窗口、BufferedPcmWriter 與 OPFS 寫入。React 測試頁不是完整產品頁；正式 gateway 帳號與 429 路徑另外透過 HTTP 整合測試驗證。

輸入為 16 kHz 合成音訊，正常切段，包含持續發聲與短暫停頓。模擬 ASR 300 毫秒、翻譯 100 毫秒。持續輸入 600 秒，包含停止與尾段處理總共 600.56 秒。

## 虛擬時間與 HTTP 回歸

| 10 分鐘虛擬情境 | ASR 請求 | 最終字幕／翻譯 | 音訊丟段／漏譯 |
| --- | --- | --- | --- |
| 快速模式 | 500 | 500／500 | 0／0 |
| 正常模式 | 400 | 400／400 | 0／0 |
| 正常＋15 秒 429＋一次 503 | 400 | 391／391 | 0／0 |

故障情境等待期間會合併尚未送出的字幕，因此字幕數較少；測試另比對合併前後所有 ASR 文字相同，確認不是漏段。該情境共 393 次翻譯請求：391 次成功、1 次 429、1 次 503，恢復後補翻完成。

另驗證同語言字幕不阻塞、兩筆並行、節流模式、1／2 秒重試、空白譯文、講者更新不重翻、人工編輯拒絕舊結果、取消與新會話隔離、尾句補翻、手動模式僅等待已啟動翻譯、設定切換、60 秒期限、滿 ASR 佇列停止、本文讀取逾時及 10,000 筆字幕只顯示 500 筆。

HTTP 整合測試從新暫存目錄與最小環境啟動真正的 gateway，沒有載入專案 `.env`；兩個測試帳號共用 IP，驗證各自額度、gateway 在上游前拒絕超額請求、上游 429 等待時間傳遞，以及 SDK 不會額外重試 429。

TypeScript 檢查、build、model-adapter／translation-policy／diarization／OPFS／transcript-export smoke 均通過。

## 重跑與啟用

```sh
npm run caption:regression
npm run caption:background:smoke
npm run caption:gateway:smoke
npm run caption:local-test
```

最後一個指令會印出 localhost 網址；在支援 OPFS 的瀏覽器開啟後，自動跑滿 10 分鐘。測試頁只允許呼叫同 origin 的四個測試路徑；不使用正式 gateway、真實 API key 或實際麥克風。報告寫入 `experiment/evaluation-reports/caption-local-10min.json`；測試完成後關閉伺服器並移除該測試建立的 OPFS 音訊與快照。

需要短測試時：`npm run caption:local-test -- --seconds 30 --report /tmp/caption-short.json`。短測試不可宣稱完成 10 分鐘驗收。

部署端需重啟 gateway 使新限流設定生效，並提供新建置的前端；本次僅在本機完成 build，未重啟使用中的正式服務、未部署。

## 尚未驗證

- 真實模型、網路、真實語音辨識準確度與供應商配額。
- 完整產品頁的帳號／背景同步／講者識別全部並行運行，以及不同瀏覽器與硬體。
- 兩小時以上的穩定性；本次僅完成 10 分鐘實際運行。
- 不支援 OPFS 的瀏覽器仍使用既有 256 MB 記憶體錄音上限，無法承諾兩小時。
- ASR 單筆耗時高於切段間隔時仍可能積壓；本次沒有提高並行或佇列上限。供應商長期限流也會影響延遲，超過 60 秒的尾句補翻會保留未完成內容。
