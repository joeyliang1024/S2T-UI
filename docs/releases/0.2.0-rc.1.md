# 0.2.0-rc.1 — Web/Python architecture prerelease

[繁體中文](0.2.0-rc.1.zh-TW.md)

This prerelease separates the React web frontend and Python backend. The release targets an exact commit on `codex/feature-python-backend`; it does not indicate a merge into `main`. The acceptance limits below remain in effect.

## Changes

- Nginx hosts the production frontend; asynchronous Python replaces the old Node Gateway/Electron application runtime.
- Components live in `frontend/`, `backend/`, `data/`, `models/` and `deploy/`, with separate environment files. Default ports are 5173/8787. `npm run dev` starts both services.
- Compose starts both components. Kubernetes runs one frontend and two complete backend Pods sharing PostgreSQL/MinIO/Redis, with migration before rollout.
- Sign-in uses NT/password without a duplicate Account field; legacy internal data remains compatible. Voiceprint sharing requires trusted department approval and consent.
- Translation matches source text against `jargon`/`az_jargon_listen` in `data/jargon/jargon_en.csv`, renders `{glossary}` per request and reuses unchanged parsed data.
- Normal capture remains **3000ms/250ms**. The display punctuation threshold increases from **24 to 40 characters** while preserving explicit boundaries, speaker changes, frozen groups and existing limits. The four-second capture experiment was withdrawn.
- Navigation icons share themed styling, animation/focus states and reduced-motion behavior.

## Reliability and performance

Local OPFS commits and network uploads have independent lifecycles. Progress/cleanup follow durable acknowledgements, with bounded retries, reload recovery, immutable remote chunks and recording finalize/delete race protection. Slow uploads no longer directly occupy the local writer queue.

Python uses bounded async model pools, small-ASR memory processing, early admission control, short SQL transactions and batched idempotency cleanup. Per-Pod exporters serialize metrics outside API workers. Grafana and Server-Timing separate model round trips, queueing and browser rendering.

Playwright supports local Chrome/Edge/Chromium fallback. Browser-test process-tree cleanup prevents successful tests from timing out on lingering descendants. Chinese/English operational documents, build registry arguments, worker/connection budgets and reproduction steps are synchronized. Raw experiment history stays local and ignored; curated results and executable tests remain versioned.

## Verification and limits

- Frontend type/architecture checks, 54 unit scripts and production build passed. Recorded Python regression: 84 passed, one skipped. Deployed Web, two-Pod, monitoring and recording-persistence checks passed.
- Historical capacity baseline: 500 distinct test NT identities for 600 seconds at one ASR→translation chain every three seconds; 100,000 completed chains, zero HTTP failures/retries/drops, and 500 recordings totaling 9.6GB SHA256-verified and cleaned.
- **Two-second extreme cadence failed.** Synchronized browser translation P90 **3.023s** failed the strict under-three-second objective. The 500-user load test was not rerun after UI/documentation updates.
- ASR and translation mocks each wait 500ms. Results do not establish 500 physical browsers, real inference compute, WAN behavior or all background workloads running simultaneously.
- Chrome recovered 58,754,560 bytes after 600 seconds of blocked upload through 307 commits without capture pressure. The separate 96kHz/30-times-real-time test recovered 115,200,000 bytes. Disk/quota failure can still cause protective pauses; buffering is finite.
- npm/Python audit snapshots on 2026-10-26 reported zero known advisories. They exclude OS packages and do not guarantee absence of unknown/future vulnerabilities.
- Temporary local Whisper inference completed and was shut down; test weights/environment were removed. It is not a resident production ASR. H100/H200 hardware remains unvalidated.

## Upgrade and reproduction

Back up databases, recording objects, settings and the original authentication secret. Use separate environment files without overwriting existing credentials. Both backend Pods must share storage and the same original secret. Build the complete backend with target `audio`; pass `NPM_REGISTRY` to frontend builds. Schema migration does not restore deleted user data.
